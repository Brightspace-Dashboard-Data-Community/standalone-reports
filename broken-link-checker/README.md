# Broken Link Checker

**A standalone reporting tool for D2L Brightspace administrators**

## Overview

The Broken Link Checker is a standalone tool designed to help Brightspace administrators identify and review potentially broken links within course content.

This project is part of the **Brightspace Dashboard Data Community**, a collection of tools, dashboards, reports, and resources created to help institutions extend the functionality of D2L Brightspace through APIs, custom development, and automation.

The goal is to provide practical tools that other Brightspace administrators can explore, adapt, and implement at their own institutions.

## Download or Browse the Project

Two versions of the Broken Link Checker are provided for convenience.

### Option 1: Download the Complete Package

**[Download Broken Link Checker ZIP](broken-link-checker.zip)**

The ZIP file contains the packaged project files for downloading and setting up the tool locally or within your institution's environment.

This option is recommended for anyone who wants to download all the files together.

### Option 2: Browse the Source Files

**[View Broken Link Checker Source Files](broken-link-checker/)**

The source files have also been uploaded separately so that you can review the project directly through GitHub without downloading the ZIP file.

The source folder includes:

- `index.html` — Main application interface.
- `css/` — Stylesheets used to format and display the report.
- `js/` — JavaScript files supporting the tool's functionality.
- `README.md` — Additional documentation included with the source package.

This option is useful for developers and administrators who want to inspect the code, understand how it works, or adapt individual components.

## Getting Started

1. Download the ZIP package or browse the source files.
2. Review the included README and application files.
3. Identify any configuration settings, API endpoints, or institution-specific values that need to be updated.
4. Configure the tool for your Brightspace environment.
5. Test the tool in a non-production Brightspace environment before deploying it for regular use.

**Important:** Configuration requirements may vary depending on your institution's Brightspace permissions, API access, and hosting environment.
